Search Syntax

All searches are case-insensitive; missing images are hidden by default. Numeric and date filters accept ranges: X..Y, ..Y, X...

Basics

tagnameImages with this tag.
-tagnameExclude images with this tag.
tagA tagBImages with both tags (AND).
tagA OR tagBImages with either tag.
red*Wildcard: tags starting with "red" (e.g. red_hair, red_eyes).
*hairWildcard: tags ending in "hair" (e.g. red_hair, blue_hair).
*hair*Wildcard: tags containing "hair".
system:Open the cheat-sheet dropdown in the search bar.

Tags & categories

character:tagnameTag "tagname" in the "character" category specifically.
cat:characterImages with any tag in the given category.
tagged:trueOnly images with at least one tag. tagged:false restricts to images with no tags.
autotagged:trueOnly images with at least one auto-tag. autotagged:false restricts to images with no auto-tags.
tagcount:>=10Number of tags on the image.
rating:explicitFilter by rating (general/sensitive/questionable/explicit); highest wins.

File

name:vacationSubstring match against the filename (the path segment after the last "/"). Case-insensitive; folder names don't bleed in.
size:>=10MBFile size. Bare bytes or a unit suffix B/K/M/G/T (1024-based).
mime:pngFile type: bare bucket (png, jpeg, webp, gif, mp4, webm, cbz) or image/.../video/.... Comma = union.
type:image / type:archive / type:animatedFile-type bucket: image = jpeg/png/webp, archive = cbz/zip, animated = gif/mp4/webm. Comma = union.
width:>=1920Filter by image width.
height:<768Filter by image height.
ratio:>=1.5Aspect ratio (width / height) comparison.
duration:>=30Video duration in seconds. Non-video rows never match.
pages:>=100Comparison filter on a archive's page count. Non-archive rows count as 0 pages.
hash:abcd…Exact-match on the image's SHA-256 (case-insensitive).
id:123Exact match on the image id.
missing:trueShow images whose files are missing from disk.

Folder, source, collection

folder:path/toImages in that folder or any subfolder beneath it.
folderonly:path/toOnly images directly in that folder (no subfolders); use folderonly: for the gallery root alone.
folder:"path with spaces"Folder path with spaces (use quotes).
source:"source name"Matches any image carrying that source. An image can have several sources; this matches any of them. Bare source: matches images with no source.
collection:"collection name"Matches any image filed under that collection. An image can belong to several collections; this matches any of them. Bare collection: matches images with no collection; collection:any matches images in at least one collection.

AI & generation metadata

ai:anyAny AI-generated image (a1111 and/or comfyui metadata present)
ai:a1111Images generated with A1111/Forge
ai:comfyuiImages generated with ComfyUI
ai:noneImages with no detected generation metadata
generated:abcd1234abcdOther images sharing the same generation recipe. The hash is shown in the Generation data block on the detail page.
prompt:catSubstring match across the SD or ComfyUI prompt (whichever the image carries).
model:sdxlSubstring match against the SD model or ComfyUI checkpoint name.
sampler:dpmSubstring match against the SD / ComfyUI sampler name.
seed:12345Exact SD or ComfyUI seed.

State & ingestion

fav:true / fav:falseFavorited / non-favorited images.
inbox:true / inbox:falseInbox state: untriaged (default for added images) vs archived/curated.
date:>2024-01-01Images ingested after a date.
date:2024-01..2024-06Images ingested within a date range.
date:2024-03-15Images ingested on an exact date.
date:2024-03-15T19:23..2024-03-15T19:30Same shape with hour (T HH), minute (T HH:MM), or second (T HH:MM:SS) precision.
via:uploadHow the image was added: ingest (watcher / sync) or upload (web form).

Relations & perceptual hash

phash:<16hex>Exact perceptual-hash match. Useful via the [copy] button on the detail page's pHash row.
phash:<16hex>~4Within Hamming distance 4 (near-duplicates). Distances 0..64 accepted.
phash: / -phash:Has a perceptual hash / doesn't have one.
relation:duplicateImage is in any duplicate group.
relation:originalImage is the chosen original of a duplicate group.
relation:alternateImage is in any alternate group.
relation:versionImage is on a version chain (either side).
relation:derivativeImage is the derivative end of an edge.
relation:sourceImage is the source side of at least one derivative edge.
relation:collectionImage carries a collection label.
relation:any / relation:noneHas any declared relation / none. any includes images with a collection label.

Sort options

NewestSort by ingest date (default for most searches). Use the order toggle (↓/↑) next to the sort select to flip direction.
File sizeSort by file size, largest first.
Collection orderGroup by collection alphabetically, then by the per-image order field. Images without a collection sit at the start; images with a collection but no order sit after the numbered ones. When the search pins a single collection:, the results read in that collection's own order.
Random (⇄)Shuffle images randomly. Stable across page turns; click ⇄ again to re-shuffle.

Uploading Images

Open the Inbox from the top menu. The drop zone at the top of the grid accepts files (JPEG, PNG, WebP, GIF, MP4, WebM, or a supported archive format: cbz or zip) : drag them in or pick them through the Choose files button.

The Actions chooser (next to the search bar) applies an operation to every image in the current search; check thumbnails first to scope it to a selection, using the matching button in the batch bar.

Adding Tags

In the tag input on the image detail page:

  • Type one or more tags separated by spaces and press Add. Each whitespace-separated token becomes its own tag. Wrap a multi-word tag in double quotes to collapse internal spaces to underscores: "red hair" → red_hair. You can also use _ directly.
  • Use category:tagname to add a tag to a specific category.
  • Example: artist:"john doe" blue_eyes 1girl adds "john_doe" as an artist tag and "blue_eyes" and "1girl" as general tags.
  • Autocomplete suggestions appear as you type - use ↑/↓ arrows to navigate, Enter to select.

Tag names

  • Lowercase a-z, 0-9 and _ ( ) ! @ # $ . ~ + - : ? < > = ^; up to 200 characters.

Managing Tags

The Tags page is the catalog view.

  • Create tag declares a fresh tag (no image needed); useful for pre-seeding a vocabulary or wiring implications against unused names.
  • Create alias binds a name to an existing canonical so typing the alias adds the canonical instead.
  • Rename can keep the old name as an alias, so searches built on the old spelling keep working.
  • Alias to (selection bar) turns each selected tag into an alias of another: every image-tag row moves to the canonical and the source becomes a zero-usage alias entry. Selecting an alias row repoints it instead.
  • Merge (selection bar) folds the selected tags into one of them: pick the survivor in the dialog and the others become its aliases, their images moving over.
  • Change category (selection bar) moves the selection to another category; when the name already lives there, the optional merge folds the tag into the existing one.
  • Implications declare "tag X also implies tag Y": adding X to an image fans Y out as a dim implied row.
  • Tag details: a row's See detail button opens its page - who applies it, usage over time, aliases pointing at it, implications in both directions, and its newest images.
  • PTR lookup (shown when monloader is paired with the Hydrus PTR enabled) pulls each selected tag's known aliases and implications from the Public Tag Repository and adds them to the catalog.
  • The Origin column shows which source created each tag (you, a booru site, the PTR, an auto-tagger); Created shows when the tag entered the catalog and Last used when it was last applied to an image.

Inbox

Every newly ingested or uploaded image lands in the inbox. Flip it to archived (curated) once you've reviewed the tags.

  • Image detail: the In inbox / Archived button left of the favorite toggles the current image between inbox and archived.
  • Batch surface: the gallery's Actions chooser and the selection batch bar each carry a single Toggle inbox entry that flips every targeted row (inbox rows become archived; archived become inbox).
  • Batch clusters: while the gallery is sorted newest-first on an inbox:true search, rows are grouped into batches. Each web upload (one drop) is its own batch; files that land on disk are batched by time, a new group every 15 minutes of inactivity.

Rating & SFW Ceiling

Each image carries at most one rating tag: general < sensitive < questionable < explicit. A manual rating add overwrites whatever was on the image, even if the new level ranks below the existing one.

The footer carries the SFW ceiling: rating: sfw · sensitive · questionable · explicit. Click any level to hide images ranked above it. Right of the ceiling chooser the footer shows a N hidden images in the current search indicator when the ceiling actually filters anything, and every per-image action (gallery, batch operations on the current search, auto-tag) honours it. The footer's image / tag / collection cells stay library-wide so the status bar always reflects the true gallery shape; the per-tag usage badge in the sidebar likewise stays library-wide.

Manga, Comics & Archives

CBZ and ZIP files containing images ingest as one library row, like an image. The cover thumbnail is page 1 (natural-sorted across the archive).

The detail page for an archive gains:

  • Open in reader - opens the reader at page 1.
  • See all pages - opens a thumbnail grid of every page; click a cell to jump straight to that page in the reader.
  • A read-only Comic / manga metadata panel parsed from ComicInfo.xml at the archive root, when present.

Relations / Collections

Four operator-declared relationships between images, plus a "not related" list that stops a rejected pair from resurfacing:

DuplicateSame image, different files. One member is the chosen original.
AlternateSame subject, different rendering. Unranked group.
VersionDirected parent → child edge (earlier to newer); one parent, one child.
DerivativeDirected source → derivative edge; one source, many derivatives.
Not relatedA rejected pair the find-pairs queue won't surface again.

Open the Relations page to walk candidate pairs and clean up duplicates, or use Add a relation on any image's detail page to declare an edge directly; if the pair already carries one, Overwrite existing relation replaces it.

Collections are a lighter grouping outside the relation graph. An image can belong to several, each with its own order. Edit them from the detail page's Collections row ([+ add], [edit], [×]); the Collections page renames, reorders, or dissolves one across all its members.

Sources & Lookups

A source records where an image came from, and an image can carry several. Edit them from the Sources row on the detail page, with [set primary] to pick the one that search and refresh follow. Each source also carries the artist's original link, commentary, and any pulled annotations.

A lookup uses a paired monloader to fill those sources for you. On the detail page, [refresh] re-pulls one source's tags, commentary and notes; Lookup reverse-searches an image against boorus and the Hydrus PTR to backfill its tags and sources. The batch Lookup action does the same across a whole search or selection.

Keyboard Shortcuts

Press ? on any page to open the cheat-sheet overlay.
