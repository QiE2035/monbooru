Search Syntax

Basics

SyntaxDescription
tagnameImages with this tag.
-tagnameExclude images with this tag.
tagA tagBImages with both tags (AND).
tagA OR tagBImages with either tag.
red*Wildcard: tags starting with "red" (e.g. red_hair, red_eyes).
*hair*Wildcard: tags containing "hair".
system:Open the cheat-sheet dropdown in the search bar.

Tags & categories

SyntaxDescription
character:tagnameTag "tagname" in the "character" category specifically.
cat:characterImages with any tag in the given category.
tagged:trueOnly images with at least one tag. tagged:false restricts to images with no tags.
autotagged:trueOnly images with at least one auto-tag. autotagged:false restricts to images with no auto-tags.
tagcount:>=10Number of tags on the image (counts every row, including implied tags fanned out from an implication).
rating:explicitFilter by rating (general/sensitive/questionable/explicit). When an image carries more than one rating tag the highest wins. The footer's sfw level corresponds to rating:general.

File

SyntaxDescription
name:vacationSubstring match against the filename (the path segment after the last "/"). Case-insensitive; folder names don't bleed in.
size:>=10MBFile size comparison. Accepts bare bytes or a unit suffix: B, K/KB/KiB, M/MB/MiB, G/GB/GiB, T/TB/TiB. Every unit is 1024-based.
mime:pngFile-type filter. Accepts the bare bucket (png, jpeg, webp, gif, mp4, webm, cbz) or the image/... / video/... form. Comma-separates as a union.
type:image / type:archive / type:animatedNarrow by file-type bucket. image = jpeg/png/webp/gif/mp4/webm, archive = cbz/zip (manga, image-zip..), animated = gif/mp4/webm. Comma-separates as a union.
width:>=1920Filter by image width.
height:<768Filter by image height.
ratio:>=1.5Aspect ratio (width / height) comparison.
duration:>=30Video duration in seconds. Non-video rows never match.
pages:>=100Comparison filter on a archive's page count. Non-archive rows count as 0 pages.
hash:abcd…Exact-match on the image's SHA-256 (case-insensitive).
id:123Exact match on the image id.
missing:trueShow images whose files are missing from disk.

Uploading Images

Use the Upload page to add images directly through your browser.

  • Select one or more files (JPEG, PNG, WebP, GIF, MP4, WebM, or a supported archive format : cbz or zip).
  • Optionally add tags that will be applied to all uploaded files.
  • Choose a destination folder (e.g. 2026/april) to place the files under; leave blank to save at the gallery root. Missing folders are created automatically.

From the gallery, open the Actions chooser (button next to the search bar, or press a) to save the search, add/remove tags, auto-tag, move, or delete every image in the current search. To scope an action to a few images, check their thumbnails and use the corresponding button in the batch bar.

Adding Tags

In the tag input on the image detail page:

  • Type one or more tags separated by spaces and press Add. Each whitespace-separated token becomes its own tag. Wrap a multi-word tag in double quotes to collapse internal spaces to underscores: "red hair" → red_hair. You can also use _ directly.
  • Use category:tagname to add a tag to a specific category.
  • Example: artist:"john doe" blue_eyes 1girl adds "john_doe" as an artist tag and "blue_eyes" and "1girl" as general tags.
  • Autocomplete suggestions appear as you type - use ↑/↓ arrows to navigate, Enter to select.

Tag names

  • Lowercase only: a-z, 0-9, _, (, ), !, @, #, $, ., ~, +, -, :, ?, <, >, =, ^
  • Maximum 200 characters.

Managing Tags

The Tags page is the catalog view.

  • Create tag declares a fresh tag (no image needed); useful for pre-seeding a vocabulary or wiring implications against unused names.
  • Create alias binds a name to an existing canonical so typing the alias adds the canonical instead.
  • Alias on a non-alias row turns it into an alias of another tag: every image-tag row moves to the canonical and the source becomes a zero-usage alias entry.
  • Implications declare "tag X also implies tag Y": adding X to an image fans Y out as a dim implied row.

Inbox

Every newly ingested or uploaded image lands in the inbox. Flip it to archived (curated) once you've reviewed the tags.

  • Gallery toolbar: the ✱ button left of the favorites toggle filters to the inbox.
  • Image detail: the ✱ button left of the favorite toggles the current image between inbox and archived.
  • Batch surface: the gallery's Actions chooser and the selection batch bar each carry a single Toggle inbox entry that flips every targeted row (inbox rows become archived; archived become inbox).

Rating & SFW Ceiling

Each image carries at most one rating tag: general < sensitive < questionable < explicit. A manual rating add overwrites whatever was on the image, even if the new level ranks below the existing one.

The footer carries the SFW ceiling: rating: sfw · sensitive · questionable · explicit. Click any level to hide images ranked above it. Right of the ceiling chooser the footer shows a N hidden images in the current search indicator when the ceiling actually filters anything, and every per-image action (gallery, batch operations on the current search, auto-tag) honours it. The footer's image / tag / collection cells stay library-wide so the status bar always reflects the true gallery shape; the per-tag usage badge in the sidebar likewise stays library-wide.

Manga, Comics & Archives

CBZ and ZIP files containing images ingests as one library row, like an image. The cover thumbnail is page 1 (natural-sorted across the archive).

The detail page for an archive gains:

  • Open in reader - opens the reader at page 1.
  • See all pages - opens a thumbnail grid of every page; click a cell to jump straight to that page in the reader.
  • A read-only Comic / manga metadata panel parsed from ComicInfo.xml at the archive root, when present.

Relations

Five operator-declared relationships between images, plus a "not related" rejection list:

  • Duplicate - same image, different files. Members live in a group with a chosen original (the canonical representative).
  • Alternate - same subject, different rendering. Members live in an unranked group; no member is privileged.
  • Version - directed parent → child edge. Each image has at most one parent (the earlier version) and at most one child (the newer version).
  • Derivative - directed source → derivative edge. A derivative has exactly one source it is based on; a source can carry many derivatives.
  • Not related - a rejected pair recorded so the find-pairs queue never resurfaces it.

Open the Relations page to start a session to walk candidate pairs, and cleanup duplicates.

Two duplicates walkers cover the cleanup:

From any image's detail page, Add a relation opens a dialog for declaring an edge against another image directly without going through a session.
